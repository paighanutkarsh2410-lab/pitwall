# Architecture

## The stream

| Topic | Partitions | Kept | Carries |
|---|---|---|---|
| `pitwall.raw` | 6 | 2 h | Everything the replayer sends |
| `pitwall.telemetry` | 6 | 2 h | `car.telemetry`, `car.position` |
| `pitwall.timing` | 6 | 24 h | Laps, positions, gaps, pit stops, tyre stints |
| `pitwall.race` | 1 | 24 h | `session.info`, `race.control`, `weather` |
| `pitwall.deadletter` | 1 | 24 h | Events that broke the schema, with the reason |
| `pitwall.board` | 1 | compacted | The latest timing board |
| `pitwall.strategy` | 1 | compacted | The latest strategy model |

- **Keys.** Events are keyed by car number, so one car's events stay in order on one partition.
  Race-wide events go to a one-partition topic, so they stay in order too.
- **Runs.** Every message carries a `pitwall-run` header. Run ids start with the run's start time
  in milliseconds, so they sort by age. A service reading several partitions can tell a new run
  from a straggler of an old one whatever order their messages arrive in. (An early version used
  random ids, and a replay restarted mid-race could hand the board back to the old run.)
- **Snapshots.** Board and strategy snapshots go to compacted topics. A new pitwall-api replica
  reads the latest of each from the start of the topic and is up to date at once.

## State

**timing** and **strategy** are projectors. They fold events into a model
([`timing.py`](../src/pitwall/timing.py), [`strategy.py`](../src/pitwall/strategy.py)) and
publish snapshots at a capped rate: four a second for the board, one for strategy. They commit no
offsets, so every start reads the retained log from the beginning and rebuilds the model. That
makes a crash, a reschedule or a new canary safe: the pod catches up by itself.

The models are plain Python with no I/O, so the unit tests drive them directly.

## Joining mid-race

Some things happen once: the grid order, a car's tyre stint, a pit stop, a flag. A replay that
starts at lap 30 first sends everything before lap 30 except telemetry and positions (about
10,000 events, sent at once), then plays on at the chosen speed. A service that joins halfway
still has the whole race so far.

## Strategy

- **Degradation** is the slope of lap time against tyre age over a stint's clean laps. A clean
  lap is not an out-lap or an in-lap, not under a safety car, VSC or red flag, and within 107% of
  the stint's median.
- **Negative degradation** is real. At São Paulo 2024 the track dried through the race, so cars
  got faster on the same tyres.
- **Pit loss** is the field's median time in the pit lane, leaving out red-flag stops.

## History

ingest writes telemetry (with COPY) and laps (as upserts) to TimescaleDB in batches. The
`telemetry` hypertable is partitioned by the time Pitwall *received* each sample, not the time
the car recorded it in 2024. That way a retention policy (3 days) drops old replays without
touching new ones.

## On Kubernetes

- **Charts.** Two Helm charts. `pitwall-data` holds Redpanda and TimescaleDB as StatefulSets with
  volumes. `pitwall` holds the five services, all running one image.
- **Deployment.** Argo CD deploys both from `deploy/` with an app of apps. Sync waves put the data
  first. Automated sync with prune and self-heal means the cluster is whatever Git says.
- **Hardening.** Services run as a non-root user with a read-only root filesystem, every Linux
  capability dropped, the RuntimeDefault seccomp profile and no service-account token. Their only
  writable space is an in-memory `/tmp`.
- **Probes.** `/readyz` is ready only while the worker is connected and consuming; `/healthz`
  says the process is alive. A worker that fails (Redpanda not up yet, a lost connection) is
  restarted with backoff, and the pod reports not-ready meanwhile.
- **Secrets.** The database password is generated by `scripts/cluster-up.sh` straight into a
  Secret, and appears in no file.
- **Promotion.** CI promotes images by committing the new tag to the local environment's values.
  The cluster runs exactly what CI built, scanned and signed, and Git records every deploy.
